# 提示词、水印、生图能力说明

这个整理包里的提示词、文字水印和豆包生图能力都在 `app.py` 中，不是单独的 prompt 文件。

## 1. 风格与提示词入口

位置：

```text
app.py:386
```

`GENERATION_STYLE_OPTIONS` 定义用户可选的生成风格，例如：

```text
半身职业头像
全身职业形象照
带文字品牌形象照
半身带文字职业头像
高端美式证件照
明星级职业头像（1:1）
```

位置：

```text
app.py:410
```

`selected_generation_labels(style_config)` 会读取前端传来的风格字段，包括：

```text
textRegionEnabled
singleStyle
combinationStyles
generationStyles
```

然后转换成实际要生成的中文风格标签。

## 2. 服装、背景、视觉风格提示词

位置：

```text
app.py:469
```

`build_prompt_config(style_config)` 会把前端选项转换成提示词中的服装、内搭、领型、扣子、背景、视觉风格。

相关字段包括：

```text
jacketColorV2
innerColor
jacketStyleV2
innerStyle
collarStyle
buttonState
backgroundType
visualStyle
customJacketColor
customInnerColor
customBackgroundColor
```

## 3. 核心生图提示词

位置：

```text
app.py:620
```

`build_headshot_prompt(label, style_config)` 是核心单张图片提示词生成函数。

它会根据不同 label 生成不同提示词：

```text
半身职业头像
全身职业形象照
带文字品牌形象照
半身带文字职业头像
明星级职业头像（1:1）
其他职业形象照变体
```

带文字版本会在提示词中要求模型：

```text
构图需要在画面左下角或底部安全区域预留干净留白，供程序后期叠加品牌文字水印。
不要在图片中生成任何文字、字母、数字、logo、水印、签名或排版元素；最终水印会由程序后期叠加。
```

位置：

```text
app.py:729
```

`build_headshot_set_prompt(labels, style_config)` 会把多张图的风格合并成一次豆包请求，要求同一人物身份一致，同时让背景、构图、光线和职场氛围有差异。

## 4. 文字图片与品牌水印

位置：

```text
app.py:457
```

`brand_text_config(style_config)` 读取前端传来的品牌文字：

```text
mainTitle / brandTitle
subtitle / brandSubtitle
infoLine / brandMeta
```

默认值：

```text
Portrait ID.
Redefine Identity
SERIES 01 // MINIMALIST
```

位置：

```text
app.py:830
```

`apply_brand_watermark(image_path, style_config)` 是真正把文字画到生成图片上的函数。

它使用 Pillow：

```text
Image
ImageDraw
ImageFont
```

支持的水印控制字段：

```text
watermarkEnabled
watermarkTitleColor
watermarkSubtitleColor
watermarkInfoColor
watermarkPosition
watermarkAlign
```

执行位置：

```text
app.py:1255
```

每张图片写入 `static/generated/` 后，都会调用：

```python
apply_brand_watermark(target_path, style_config)
```

也就是说，豆包不负责生成文字。豆包只生成干净人像图；文字水印由本地程序后期叠加。

## 5. 豆包 Seedream 生图能力

配置文件：

```text
.env
```

关键配置：

```text
IMAGE_GENERATION_PROVIDER=doubao
DOUBAO_BASE_URL=https://ark.cn-beijing.volces.com/api/v3
DOUBAO_API_KEY=本机配置，不在文档中展示
DOUBAO_MODEL=doubao-seedream-5-0-260128
DOUBAO_IMAGE_SIZE=2K
DOUBAO_RESPONSE_FORMAT=url
DOUBAO_INPUT_IMAGE_FORMAT=data_url
DOUBAO_MAX_IMAGES=12
DOUBAO_TIMEOUT_SECONDS=180
DOUBAO_ALLOW_MOCK_FALLBACK=false
```

我已把 `DOUBAO_INPUT_IMAGE_FORMAT` 改成：

```text
data_url
```

这样新整理目录可以本地独立调用豆包，不依赖旧 ngrok 公网地址。

位置：

```text
app.py:907
```

`post_doubao_generation(api_url, api_key, body)` 负责请求豆包/火山 Ark 接口。

位置：

```text
app.py:928
```

`call_doubao_seedream(source_path, labels, style_config)` 负责：

```text
读取 DOUBAO_API_KEY
拼接 /images/generations
选择模型
把参考图转成 data URL
组装 prompt
设置 sequential_image_generation
设置 max_images
设置 watermark=false
保存豆包返回图片
```

请求体核心字段：

```text
model
prompt
image
size
sequential_image_generation
sequential_image_generation_options.max_images
response_format
watermark=false
```

位置：

```text
app.py:983
```

`generate_image_assets(...)` 根据 `.env` 的 `IMAGE_GENERATION_PROVIDER=doubao` 选择豆包生成。

位置：

```text
app.py:946
```

`/api/generate` 是前端最终调用的生成接口。它会上传图、选择风格、调用豆包、保存结果、叠加文字水印、写入数据库。

## 7. Cloudflare Worker 线上生图版本

原项目还有一套线上部署版本，已经复制到：

```text
cloudflare-worker/
```

包含：

```text
cloudflare-worker/src/worker.js
cloudflare-worker/migrations/
cloudflare-worker/wrangler.jsonc
cloudflare-worker/package.json
cloudflare-worker/package-lock.json
cloudflare-worker/CLOUDFLARE_DEPLOY.md
cloudflare-worker/ark-seedream-image-provider.md
```

这套版本和本地 Flask 版不是同一个运行入口。

本地 Flask 版入口：

```text
app.py
```

线上 Cloudflare Worker 版入口：

```text
cloudflare-worker/src/worker.js
```

Worker 版豆包 Seedream 位置：

```text
cloudflare-worker/src/worker.js
```

关键函数包括：

```text
generateImageSetWithProvider
generateSeedreamImageSet
buildHeadshotSetPrompt
resolveSeedreamImageModel
generatedImageItemToAsset
```

Worker 版使用：

```text
D1 数据库
R2 私有对象存储
Wrangler 部署
DOUBAO_API_KEY 或 ARK_API_KEY secret
```

注意：Worker 版 API Key 不写在文件里，需要用 Wrangler secret 配置；本地 Flask 版 API Key 在 `.env` 中。
